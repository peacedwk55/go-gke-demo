เอกสาร — หน้านี้เอง

เขียนคำอธิบายทุกไฟล์ แล้ววางไฟล์ HTML ไว้ที่ root ของรีโป

พบตอนตรวจว่าไฟล์ใหม่เข้า Docker build context ไหม (ด้วย probe COPY . /ctx) เจอว่า trivy.yaml, .yamllint.yml และ scripts/ หลุดเข้าไปอยู่ก่อนแล้ว เพราะถูกเพิ่มเข้ารีโปหลังจากเขียน .dockerignore ไปแล้ว — เป็นเหตุผลว่าทำไมควร probe context เป็นระยะ ไม่ใช่เชื่อว่า ignore file ตามทัน

ข้อสรุปของทั้งเก้าขั้น บั๊กที่สำคัญเกือบทุกตัวในรายการนี้ผ่าน code review ได้สบาย ๆ เพราะมันดูถูกต้อง — pipefail ที่กลับหัว, check ที่จับตัวเอง, ignore file ที่ตามไม่ทัน, drain delay ที่สั้นไป 4 วินาที ทั้งหมดถูกพบเพราะเอาไปรันแล้ววัดผล ไม่ใช่เพราะอ่านโค้ดซ้ำ

วงจรชีวิต — โค้ดเดินทางอย่างไร

จากที่ developer กด commit จนถึง pod รับ traffic และวนกลับ ทุกลูกศรในนี้เป็นระบบอัตโนมัติ ยกเว้นขั้นที่ระบุไว้ว่าต้องใช้คน

1commit — developer merge เข้า main โค้ดแอปหรือ config.env ก็เดินทางเส้นเดียวกัน
2CI: test — gofmt, go vet, go test -race ถ้าไม่ผ่านจบตรงนี้ ไม่มีการ build
3CI: invariants — กฎ 7 ข้อของรีโป แล้ว render manifest ทั้งสอง overlay ผ่าน kubeconform และสแกน IaC บนผลที่ render แล้ว
4CI: build → scan → push — build ลง tarball ในเครื่องก่อน สแกน Trivy แล้วจึง push ขึ้น Docker Hub ด้วย tag sha-<sha> ลำดับนี้สำคัญ: สแกนหลัง push แปลว่า image ที่มีช่องโหว่ถูกดึงไปใช้ได้แล้ว
5CI: bump — kustomize edit set image เขียน path ของ Artifact Registry ด้วย tag เดิม แล้ว commit กลับพร้อม [skip ci] นี่คือการเขียนออกไปข้างนอกอย่างเดียวที่ CI ทำ
6ArgoCD sync — ArgoCD ที่อยู่ในคลัสเตอร์เห็น commit แล้ว apply เอง CI ไม่เคยแตะคลัสเตอร์
7GKE ดึง image — ผ่าน Artifact Registry remote repo ไม่ใช่จาก Docker Hub ตรง ๆ เพื่อไม่ให้ทั้งคลัสเตอร์แชร์ rate limit ของ NAT IP เดียว
8pod เริ่มทำงาน — startupProbe เปิดทางให้ก่อน (30 × 2 วินาที) แล้ว readinessProbe จึงปล่อยให้ traffic เข้า ส่วน livenessProbe เฝ้าดูว่าโพรเซสค้างไหม โดยไม่แตะ dependency
9rollout จบแบบไม่มี downtime — pod เก่าได้ SIGTERM → /readyz เป็น 503 ทันที → รอ 5 วินาทีให้ EndpointSlice อัปเดต → drain request ที่ค้าง → flush trace แล้วออกด้วย exit 0
10สังเกตการณ์ — metrics เข้า Prometheus ผ่าน ServiceMonitor, log เข้า Loki ผ่าน Alloy, trace เข้า Tempo ผ่าน OTLP ทั้งสามผูกกันด้วย trace_id
11scale — HPA ปรับ 2–6 replica ตาม CPU เทียบ request โดย ArgoCD ไม่กดกลับ เพราะมี ignoreDifferences คู่กับ RespectIgnoreDifferences
12rollback — git revert แล้ว ArgoCD sync กลับ tag เดิม ไม่มีเครื่องมือแยกที่พฤติกรรมต่างจากเส้นทาง deploy
13เก็บของ — terraform apply -var deletion_protection=false แล้วจึง terraform destroy สองขั้น เรียงลำดับ ต้องใช้คน โดยเจตนา
